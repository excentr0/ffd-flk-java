# Сверка кодов ФЛК в ответах ОФД

Область: только коды ошибок ФЛК из столбца «Код ошибки» таблиц возврата 32–39 трёх приложенных PDF и список отказных ошибок для `errorStatus=2` таблицы 41. Не каталог всех HTTP/API-кодов и не нормативное одобрение входного контроля ККТ → ОФД. Строки 14–29 учтены отдельно в `ffd-*.json`/`row_ledger`; исходные PDF не менялись.

| ФФД | Всего числовых кодовых ячеек в таблицах 32–39 | Не-ФЛК (400, 405, 409, 417, 419) | Добавлено в `flk-returns-*.json` | По таблицам 32, 33, 34, 35, 36, 37, 38, 39 |
|---|---:|---:|---:|---|
| 1.05 | 217 | 56 | 161 | 12, 12, 11, 10, 47, 47, 11, 11 |
| 1.1 | 231 | 56 | 175 | 12, 12, 11, 10, 54, 54, 11, 11 |
| 1.2 | 217 | 56 | 161 | 12, 12, 11, 10, 53, 41, 11, 11 |

PDF-страницы считаются от первой физической страницы. Подпись таблицы и сетка иногда разделены страницей; привязка устанавливается по координате подписи относительно сетки, а не по номеру страницы в одиночку. Каждая сохранённая строка содержит исходные ячейки, bbox кодовой ячейки, версию, номер таблицы, документ и положение строки. Повторный номер кода не объединяется: например, строка таблицы 32 p.82/128/149 с HTTP `400`, кодом ошибки `420`, тегом `<имя тега>` отличается от иных таблиц/контекстов. Строка 536 с `userInn` и HTTP `200` находится в таблице 36 p.99/145/168. Код 405 отсутствует в новом каталоге намеренно: в исходнике это не-ФЛК отказ/карантин (включая HTTP 400 и 202); сырой источник остаётся в PDF и `ffd-*.json → pages`.

Таблица 41 `errorStatus=2` перечисляет ровно 12 кодов отказного ФЛК: в 1.05/1.1 `420, 421, 422, 423, 424, 502, 503, 505, 506, 507, 510, 511`, в 1.2 последний номер — `533` вместо `511`. Это связь категории статуса с напечатанным списком, а не присвоение кода ФЛК `2` и не исчерпывающий список предупреждений.

Проверка: `references/data/scripts/extract_flk_returns.py --check` регенерирует каталоги из оригинальных PDF с проверкой SHA-256 и отклоняет неожиданный номер в кодовом столбце. `audit_flk_returns.py` независимо сверяет через Poppler положение и номер каждой из 497 включённых ячеек, а также весь кодовый столбец 665 исходных числовых вхождений по таблице и номеру, включая 168 исключённых. Детектор границ сеток и заголовков при этом тот же pdfplumber, а Poppler проверяет текст/координаты, не семантику. Тесты закрепляют количества по каждой таблице, 420/536 и списки `errorStatus=2`.

**Ограничение:** текст сообщения, длинные объединённые ячейки и применимость/условия ФЛК не утверждены визуально для каждой строки. Пустой столбец в строке может быть объединён с соседним в PDF; его нельзя заполнять или интерпретировать без просмотра оригинала. `semantic_review` логических правил по-прежнему pending, исполняемых правил — 0. Независимые субагенты по растру семи страниц подтвердили HTTP 400/код 420 (p.82/128/149), HTTP 200/код 536 (p.99/145/168) и в 1.2 список `errorStatus=2` с кодом 533 (p.185); Tesseract не дал пригодных совпадающих строк, поэтому OCR не засчитан как отдельное подтверждение. Их проверки полной геометрии таблиц не дали надёжного построчного реестра; итоговый полный счёт кодовых ячеек опирается на описанную автоматическую сверку двух извлекателей, не на выборочную визуальную сверку.

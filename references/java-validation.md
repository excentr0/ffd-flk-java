# Корректная реализация ФЛК на Java

## Представление документа

Узел TLV должен сохранять тег, исходную длину/байты, смещение и список дочерних вхождений для STLV. Типизированная модель допустима, только если не теряет повторы/байтовые длины/неизвестные теги и различает отсутствие и пустое значение. Индекс `Map<Integer,List<Node>>` строится отдельно для каждого родителя; итоговый JSON-объект, уже перезаписавший duplicate keys, не позволяет доказать проверку повторяемости.

Правило с путём `items.providerData.providerInn` относится к конкретному предмету расчёта и его поставщику. Нельзя взять любой `providerInn` из общего индекса документа. Поля схожих названий/номеров на разных уровнях не взаимозаменяемы.

## Числа и деньги

- Для десятичных расчётов используй BigDecimal из исходных десятичных строк/точного декодирования. Не `new BigDecimal(double)` и не double/float.
- Для денег, гарантированно выраженных в копейках, возможен long с `Math.addExact`/`multiplyExact`, если диапазон источника действительно помещается в long. Сам по себе UINT64 такой гарантии не даёт.
- UInt16/UInt32 декодировать как unsigned; UINT64 выше 2^63−1 требует BigInteger или явно корректных unsigned операций, особенно при суммировании.
- Точное равенство BigDecimal — `compareTo(...) == 0`, не equals (масштаб не должен создавать ложную ошибку).
- Допуск — `abs(actual.subtract(expected)).compareTo(tolerance) > 0` для нарушения, если источник подтверждает включительные границы. Переведи «1 рубль» и «1 копейка» в единицы модели с явной ссылкой. Не добавляй универсальный epsilon.
- Округление/scale/порядок операций/точность количества брать из правила. Формула с ценой и количеством не разрешает произвольное промежуточное округление.
- Отсутствующий optional tag не превращать в BigDecimal.ZERO без установленной семантики конкретной суммы.

## Байты, строки и даты

- Проверка длины TLV относится к байтам VALUE. Длина STLV — сумма длин вложенных заголовков TLV и VALUE. Проверяй отсутствие остатка/обрезанного заголовка и выходов за границу до доступа к памяти.
- Кодировку, endian и FVLN/VLN/BYTE/UNIX_TIME/STLV расшифровывать по приложению источника; не выбирать UTF-8/CP866/порядок байтов по памяти. Не переносить тип JSON-представления после преобразования на исходное TLV без проверки преобразования. Например, 1077 в таблицах — `BYTE[]`, длина 6 и числовой диапазон `[0,4294967295]`: это не разрешение трактовать любые 6 байт как обычный UInt48 и сравнивать его с UInt32 без правила декодирования фискального признака.
- Строковый regex из PDF сохранять дословно в raw. Проверить повреждения переносов/экранирования до преобразования в Java Pattern. `matches()` и `find()` не взаимозаменяемы.
- Нельзя измерять длину протокольной строки через String.length вместо длины исходных байтов. Контроль суррогатных символов и неверного декодирования — отдельная структурная задача.
- Календарные месяцы не равны 30 дням. Для `minusMonths(6)` нужен определённый ZoneId и источник временной базы; не заменять на Duration.ofDays(180).
- Время приёма/текущее время передавать через контекст и фиксировать в тестах. Не делать Instant.now() внутри каждой проверки.

## Результаты и зависимости

Результат содержит ruleId, код/категорию источника, версию/документ, точный путь с индексом контейнера и причину. Разделять fatal error, warning, info, not-evaluated и policy/data blocker. Не назначать severity только по первому разряду кода.

Криптографическая достоверность ФН, договор, статус регистрации, состояние сессии и исторические документы — внешние зависимости. Передавай снимок контекста либо явно выделенную границу сервиса. Pure validator не должен выполнять сетевые вызовы в середине обхода тегов.

Неизвестный/неподдерживаемый AST блокирует сертификацию соответствующей проверки. Не пропускать исключения через catch(Exception) с итогом VALID. Отсутствие вычисленного нарушения не равно доказательству корректности, если правило не выполнено.

## Компиляция и тесты

Придерживаться Java проекта. При отсутствии проекта примеры должны быть framework-free; Java 17 — совместимый ориентир, а не требование заменить установленную JVM. Проверять `javac --release 17` для таких примеров.

Свойства для тестов: изменение вложенного реквизита влияет только на соответствующий путь; разрешённые повторные STLV не вызывают singleton duplicate; сумма на точной границе допуска проходит, на одну минимальную единицу за границей — нет; календарный шестимесячный сдвиг через февраль отличается от 180 дней; UINT64 выше Long.MAX_VALUE не становится отрицательным; отсутствие контекста/неполная формализация не выдаёт безусловный VALID.

Проверки по источнику тестируй положительными и отрицательными примерами. Мутация ожидаемого результата теста без источника запрещена. Для таблиц, исключённых из KKT→OFD, тестировать именно исключение, а не заставлять кассу проходить PПФД-only rule.

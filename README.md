# ffd-flk-java

Переносимый skill для разработки и проверки Java-ФЛК **ККТ → ОФД** для ФФД **1.05, 1.1 и 1.2**. Инструкции: [SKILL.md](SKILL.md). Все пути разрешаются относительно каталога скилла; соседние рабочие проекты не требуются.

## Статус: черновик

**Это не готовый валидатор и не полностью проверенная нормативная база.** Сохранены 2066 контекстных записей полей и первичные источники. Синтаксически разобранное правило не означает подтверждённую семантику: сейчас **0 утверждённых / 0 исполняемых логических правил**.

Сохранение вложенных STLV-путей и структурный учёт проверяются тестами. Отдельно добавлены `references/data/flk-returns-*.json` — кодовые ячейки ФЛК в ответах ОФД по восьми видам ФД и связь `errorStatus=2` с перечисленными в PDF кодами отказа. Это источник-ориентированная запись кода, **не** разрешение исполнять проверку на входе ККТ → ОФД. Полная независимая сверка связок **условие → проверка → код ошибки**, в том числе для вложенных реквизитов и объединённых ячеек, **не завершена**. Кардинальность, формулы, единицы, область применимости и примечания требуют дальнейшего утверждения. Неполнота базы не является причиной отклонять конкретный фискальный документ.

Подробности: [проверка PDF и обнаруженное исправление](review-evidence/pdf-audit.md), [сверка кодов возврата ФЛК](review-evidence/flk-return-codes.md), [данные и проверки](references/data/README.md), [coverage.json](references/data/coverage.json), [происхождение источников](references/data/sources/SOURCE-PROVENANCE.md). Некоторые DOCX не являются подтверждённой действующей сводной редакцией; PDF приказа №1050 получен со стороннего сайта и не сверен с официальным сканом.

## Состав

- `SKILL.md`, `references/` — инструкции, правила работы с источниками и Java.
- `references/data/` — JSON, схема, контрольные суммы, скрипты и тесты.
- `references/data/sources/` — исходные PDF/DOCX и извлечённый текст.
- `examples/` — Java 17 механизмы, не нормативный ФЛК.
- `evals/` — сценарии оценки скилла, не доказательство его приёмки.

## Проверка комплекта

Из корня репозитория:

```sh
shasum -a 256 -c SHA256SUMS.txt
cd references/data
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/verify_semantics.py --require-ready
```

Для проверок PDF нужен Poppler (`pdftotext`). Последняя команда **ожидаемо возвращает ненулевой код**, пока семантическая готовность не утверждена. Пересборка описана в README данных; raw-извлечение перезаписывает нормализованные JSON.
